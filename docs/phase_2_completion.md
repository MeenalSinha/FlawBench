## Implemented

* Reference registry with mandatory transcript, attribution, licence, rights confirmation, redistribution status,
  SHA-256, duplicate and collision refusal, optional explicit copy.
* Injectors: pause insertion, local tempo change (WSOLA via audiotsm), local energy reduction (dB).
* Ground-truth annotations from actual sample boundaries; source and output intervals stored separately;
  tempo annotation uses the measured stretched length.
* Config-driven severity profiles and bounds, validated at load time; plans from YAML/JSON.
* Seed policy (explicit seeds only for random placement; per-sample derived seeds; none recorded when unused).
* Transactional generation, stable ids, idempotent reruns, overwrite policy with history, batch run log with failures.
* Validator with deep content verification, source-level splits (persisted), export restricted to permitted sources.
* CLI `dataset {register-reference, list-sources, generate, validate, split, export}`; Streamlit panel with real counts
  and a validate button; roadmap updated.
* Deterministic WAV output (libsndfile PEAK timestamp disabled; found and fixed during end-to-end verification:
  a rerun initially failed because identical audio produced different bytes).

## Known limitations

* No real speech tested (see above). Quality of the WSOLA stretch on real speech has not been assessed listening-wise;
  segments are joined without crossfades, so boundary discontinuities exist and a detector could exploit them.
* Random placement is not aligned to speech or pause boundaries; pauses may land mid-word.
* Output reproducibility is verified on this environment only; a different audiotsm/numpy/libsndfile may change tempo
  output. This is detected (same id, different checksum) and needs explicit overwrite.
* WAV truncation can go undetected by libsndfile (Phase 1 limitation); FLAC truncation is rejected.
* Single-writer assumption; no file locking. A crash between file commit and manifest write leaves an orphan
  (reported by the validator, adopted by an identical regeneration).
* Output writing uses python-soundfile's low-level handle to disable the PEAK chunk; a soundfile update could break it
  (a test would fail).
* Dataset-level statistical adequacy is not claimed: split warnings are emitted below 10 sources.
* The reference size limit (`audio.max_upload_mb`) also applies to registered sources.
* Only mono/stereo up to `audio.max_channels` is accepted.

## Deferred

Pitch-variation flattening, compound flaws, speech-activity-aware placement, transcript alignment, any detection or
evaluation.

## Phase 3 readiness

Ready. Feature extraction can consume, per sample: `generated.path` (+ `reference.path` via `source_id`), sample rate,
channels, frames, and `annotation` (ground truth, reserved for evaluation only). Interfaces: `SourceRegistry.load_audio`,
`load_audio(path, generated_audio_settings(config))`, `DatasetGenerator.samples()`, `build_splits`. Audio arrays are
`(channels, samples)` float32 at the native rate, and all timestamps are sample-exact on the recording's own timeline, so
frame-level features can be indexed against intervals without a schema change. Before Phase 3: obtain real licensed or
self-recorded speech, generate a first real dataset, and listen to samples to confirm the injected flaws are audible.
